# Simulation plan

Deliverable **7** (`plan.md` §10–11, §19). The course is simulation-heavy because the learner
cannot train with real ordnance. Each simulator is a self-contained browser app in `sims/<slug>/`
(HTML + JS + Canvas/WebGL, no build step), embedded in the lessons it supports and also runnable
stand-alone.

## Shared design rules (every simulator)

| Rule | Implementation |
|---|---|
| Professional look | dark instrument-panel UI, monospace telemetry, grid/scale bars, no cartoon art |
| Difficulty | **Beginner / Intermediate / Advanced / Expert** selector changes noise, time, resources, hidden information |
| No early reveal | ground truth is generated by a seeded RNG and only revealed in the debrief after the learner commits |
| Debrief (§11) | *What you observed · What you decided · What you missed · What uncertainty existed · What professional reasoning would consider · Relevant physics · Relevant engineering · Links back to lessons* |
| Scoring | multi-criteria (safety, information quality, uncertainty reduction, resource use, recognition of unknowns, exposure) — never speed alone, never "which wire" |
| Fiction | all objects are synthetic ("Object type K-3", "fictional compound Z"), all yields are abstract units |
| Reproducible | `?seed=` URL parameter; the debrief prints the seed so a scenario can be replayed |
| Math visible | every physics panel can show the equation it is evaluating and the current numbers |

## The simulators

| Id | Name | Supports | What the learner does | What it teaches |
|---|---|---|---|---|
| **A** | Scene Assessment | 00.2, 07.1, 07.2 | 2.5D top-down/isometric scene you can pan/rotate; inspect objects, deploy virtual sensors and a robot, mark hazards, draw cordon & safe zones under limited time/resources | information gathering, cordon logic, secondary-hazard awareness, exposure minimisation |
| **B** | EOD Robot | 06.1–06.5, 06.9 | drive a tracked robot, pan/tilt camera, 2-link arm + gripper, pick sensors; simulated camera feed with occlusion & noise; battery, latency, packet loss, map with pose uncertainty ellipse | teleoperation under latency, occlusion, comms loss behaviours, uncertainty display |
| **C** | Sensor Fusion | 05.1–05.6, 09.4 | a grid of buried/hidden fictional objects; query camera, thermal, metal detector, X-ray-like, depth sensors, each with its own noise/false-alarm model and cost; update posterior; declare | Bayes, likelihood ratios, correlated errors, value of information |
| **D** | Blast Physics | 01.3–01.5, 04.1–04.4 | abstract-yield source; distance slider, pressure–time plot (Friedlander), 2D wave propagation animation (finite-difference acoustic/shock approximation), wall reflection, open vs confined, SDOF structure response & P–I diagram | scaling, reflection, impulse vs peak, confinement, structural regimes |
| **E** | Post-Blast Investigation | 08.1–08.3 | synthetic scene with fragments, damage marks, displaced objects, "photos", tape-measure tool; place hypotheses of seat location & sequence; evidence log with chain of custody | inverse reasoning, uncertainty in reconstruction, documentation discipline |
| **F** | Incident Command | 07.1–07.2 | timeline-driven scenario: reports arrive over time; request information, task sensors/robot, set isolation area, escalate, or declare insufficient evidence | sequential decisions under uncertainty; scored on reasoning, not speed |
| **G** | Robotics Engineering | 06.3–06.9, 09.5 | challenge set: obstacle course, reach target, keep comms (link budget/relay placement), minimise energy, manipulate a fictional object, noisy sensors; learner can write their own controller in JS in-browser | algorithms → behaviour; planning, control, estimation |
| **H** | Recognition Trainer | 03.1–03.4 | synthetic technical illustrations of *generic categories* (projectile, mortar-type, rocket-type, grenade-type, submunition-type, mine-type, abandoned-store, suspicious-item); classify category and choose the *category of professional response*, with explanation | why category drives response; indicators vs certainty |
| **I** | Shock-Tube & Rankine–Hugoniot explorer | 01.3, 01.4, 02.2 | pick shock Mach number, see pressure/density/temperature jumps, reflected shock, CJ point on a Hugoniot plot | shock physics made visible |
| **J** | Detection-theory lab | 05.1 | move thresholds on ROC; base-rate and cost sliders; see expected cost per m² in clearance | ROC, base rates, operating points |

## Build order
D (physics core) → I → J → C → H → B → G → A → F → E. Each simulator is committed separately.

## Python-side simulations
Programming projects (see [project-plan.md](project-plan.md)) are the "engine room" versions of
the browser sims: P01 ↔ D, P02/P03 ↔ C, P04–P08 ↔ B/G, P10 ↔ A/E, P11 ↔ B, P12 ↔ F.
